# darkfalcon95728

Hey, I'm a developer who spends most of my time between the terminal and the editor. I care about writing code that stays readable months later and systems that keep running without constant babysitting.

## What I focus on

I work primarily with **Python**. It's the language I reach for when I need to prototype quickly, glue systems together, or build something that has to process data reliably. Over time I've grown to prefer clear, explicit code over clever one-liners.

A big part of my day involves **automation**. I like turning repetitive tasks into scripts or small services so I can focus on the interesting problems. Whether it's deployment pipelines, data cleaning jobs, or internal tooling, I try to make the machine do the boring work.

**Linux** is my daily environment. I feel most productive when I can stay close to the tools that actually run the software—shell, systemd, containers, and the usual suspects in the CLI toolbox. Understanding how things work under the hood helps me debug faster and design better.

I also enjoy building and refining **developer tools**. Small utilities, scripts that save a few clicks, or internal libraries that reduce friction for a team. Good tools don't have to be complicated; they just have to fit the workflow.

## How I work

- Prefer simple solutions that are easy to reason about
- Write documentation while the context is still fresh
- Keep dependencies minimal when possible
- Test the parts that matter most

I value clear communication and practical results over buzzwords. If something is broken, I'd rather fix it than talk about how innovative the architecture is.

Feel free to look around the repos. Most of what I publish is meant to be useful or at least educational. If you spot something that could be improved, open an issue or a PR—I'm always open to better ideas.
